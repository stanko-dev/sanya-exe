# sanya.exe

Шкільна 2D top-down аркада-подарунок на JavaScript, Phaser 3.90 та Vite 7. Три рівні, 12 / 15 / 18 мультяшних суперників, пастки, постріли конфеті, фото й побажання після кожного рівня. Без крові, backend, бази даних і платних сервісів. Медіа необов’язкові: без них працюють процедурні заглушки.

## Запуск

Потрібен Node.js **22.12+** (або 20.19+) та npm.

```sh
npm install
npm run dev
```

Відкрити адресу з термінала, зазвичай **http://127.0.0.1:5173/sanya-exe/**. Для роботи потрібні клавіатура й миша; керування дотиком не реалізовано.

```sh
npm test          # перевірка прохідності карт і конфігурації
npm run build    # production → dist/
npm run preview  # локальна перевірка production-збірки
node tests/browser-smoke.mjs # необов’язкова перевірка в локальному Chrome без додаткових пакетів
```

## Керування і правила

- **WASD** — рух, миша — приціл, утримання **ЛКМ** — конфеті.
- **Esc** або кнопка **Ⅱ** — пауза з гучністю та виходом у меню.
- Рухайся між партами й тримай дистанцію. Кожен суперник має HP і завдає контактної шкоди з перезарядкою. Після влучання гравець отримує коротку невразливість.
- Відправ усіх суперників на перерву, тоді пройди до зелених дверей **угорі по центру**. Відкриється листівка з фото й кнопкою наступного рівня.
- При поразці **Restart** або **R** перезапускає поточний рівень. Після третьої листівки — фінальне привітання.
- Гучність запам’ятовується локально; прогрес проходження не зберігається. У меню є Play/Pause, перемотування та поточний час / тривалість треку. Музика стартує лише кнопкою Play; при виході плеєр зупиняється та звільняє ресурс.
- Помаранчеві клітинки — пастки. Після наступання вони червоно блимають 600 мс; вийди із зони до завершення попередження. Потім пастка завдає 35 HP і вимикається на 2500 мс. Пауза зупиняє відлік пастки.

У Windows PowerShell із забороненими `.ps1` використовуй `npm.cmd` замість `npm`. Browser smoke запускає власний headless Chrome; типовий шлях — `C:/Program Files/Google/Chrome/Application/chrome.exe`, інший можна задати змінною `CHROME_PATH`. Потрібні вільні локальні порти 5178 і 9228; скриншоти та ізольований профіль зберігаються в ігнорованій папці `test-results/`. Додаткові залежності не встановлюються.

## Фото та звуки

Підтримуються **PNG / JPG / JPEG / MP3 / OGG**. Регістр важливий для GitHub Pages. Тип ворога глобальний: одне й те саме обличчя та звук використовуються на всіх рівнях.

```text
public/media/
  menu/
    background.png            # фон меню, бажано 1280×800
    soundtrack.mp3            # музика меню / фіналу
  lvl1/
    face_lvl1.jpg            # глобальний тип 1 (наявний)
    hit_sound.ogg            # персональне влучання типу 1 (можна додати пізніше)
    reward_photo.png
    soundtrack.mp3
  lvl2/
    face_lvl2.jpg            # глобальний тип 2 (наявний)
    morda.ogg                # влучання типу 2 (наявний Ogg Opus)
    reward_photo.png
    soundtrack.mp3
  lvl3/
    face_lvl3.jpg            # глобальний тип 3 (наявний)
    nothanks.ogg             # влучання типу 3 (наявний Ogg Opus)
    reward_photo.png
    soundtrack.mp3
  traps/
    trap1/
      photo.jpg              # необов’язкове персональне фото поразки
      sound.ogg              # необов’язковий звук поразки
    trap2/                   # аналогічно; папки trap1–trap9 уже створено
  common/                     # місце для власних спільних ресурсів
```

JPG стає окремою головою поверх кольорового тіла, пропорційно вписаною в 22×24 px. Тіло рухається та обертається разом із головою; хітбокс усіх ворогів однаковий — 30×30 px. Відсутнє фото повертає процедурну голову. Фотографії листівок кадруються; персональне фото пастки показується цілком зі збереженням пропорцій.

Звуки влучання обмежені глобально за `id` типу: щонайменше 1700 мс між початками, плюс заборона повторного запуску, доки попередній звук грає. Cooldown зберігається при переходах рівнів / Restart, активний звук попередньої сцени очищається. Тип 1 має необов’язковий шлях `lvl1/hit_sound.ogg`: достатньо додати справжній файл та перезапустити dev-сервер; JavaScript змінювати не потрібно.

Наявні OGG містять **Opus**. Завантажувач Phaser отримує явний `type: 'opus'` із незміненим URL `.ogg`; наступний варіант — звичайний `ogg`. Відтворення залежить від підтримки декодера браузером. У непідтримуваному браузері персональний звук пропускається. Перейменування розширення не конвертує формат.

Відсутні ресурси взагалі не запитуються: Vite збирає список реальних файлів. Замість облич — процедурні персонажі, замість фото — намальована листівка; відсутні звуки пропускаються. Пошкоджений ресурс пропускається з попередженням у консолі. Після додавання медіа перезапусти dev-сервер або виконай нову production-збірку.

## Баланс і персоналізація

У **`src/config/levels.js`** змінюй:

- `playerConfig`: HP, швидкість, шкоду, інтервал пострілів і невразливість.
- `enemies` кожного рівня: окремі `hp`, `speed`, `damage`, `count`, `attackCooldown`, `color`, `media` для кожного типу.
- `enemyTypes`: глобальні шляхи до голів і звуків влучання. Звуки успішної контактної атаки залишаються необов’язковими `lvlN/output_sound_lvlN_M.mp3`.
- `difficulty.speedMultiplier` / `damageMultiplier`: множники застосовуються до базових параметрів ворогів один раз при формуванні конфігурації. За замовчуванням: 1.15 / 1.0, 1.3 / 1.2, 1.45 / 1.4. Кількості типів: 5/4/3, 6/5/4, 7/6/5. Гравець: 100 HP, швидкість 270, шкода 30, інтервал пострілів 190 мс.
- `title`, `room`, `subtitle`, `rewardTitle`, `wish`: назви та побажання.
- `rewardPhoto`, `soundtrack`: шляхи відносно `public/media/`.
- `obstacles`: парти й перегородки `{ x, y, w, h, kind: 'desk' | 'wall' }` у координатах 1280×800. Залишай проходи шириною щонайменше 80 px, вільну стартову позицію `(640, 692)` та доступ до виходу `(640, 122)`.

Увесь текст фінального привітання — у `src/scenes/EndScene.js`. Спільні графічні заглушки — у `src/lib/art.js`. При зміні геометрії запускай `npm test`, щоб виявити відрізані проходи. Для медіа в `common/` указуй шлях у конфігурації, наприклад `common/reward_photo.png`.

## Пастки

`traps` необов’язковий: його відсутність означає порожній список. Пастки не мають фізичних тіл, не входять до `solids` чи BFS-сітки. Конфігурація однієї пастки:

```js
{
  id: 'trap1', x: 160, y: 360, width: 48, height: 48,
  type: 'damage', // або 'instant_death'
  damage: 35, warningMs: 600, cooldownMs: 2500,
  photo: 'traps/trap1/photo.jpg', sound: 'traps/trap1/sound.ogg',
  message: 'Обережно, Саня! Ця клітинка мала власні плани.'
}
```

Координати задають центр. Після попередження перевіряється перетин із хітбоксом гравця: якщо він вийшов, шкоди немає, але cooldown все одно застосовується. `damage` використовує задану шкоду; `instant_death` обнуляє HP. Обидва типи користуються спільним механізмом невразливості 650 мс, як і контактні атаки ворогів.

Якщо гравець загинув від пастки й доступне хоча б одне її персональне медіа, екран поразки показує `message`, наявне фото та відтворює наявний звук. Якщо обидва ресурси відсутні, показується стандартна поразка. Restart зупиняє звук і створює свіжий стан рівня. Для вже описаної пастки достатньо покласти файл за налаштованим шляхом і перезапустити гру / dev-сервер; для опублікованої версії потрібні нові build і deploy. Нові пастки описуються в конфігурації, без змін ігрової логіки. Залишай вільними старт, двері, парти, стіни та вузькі проходи.

## Структура

```text
src/config/levels.js     баланс, типи суперників, карти й побажання
src/scenes/BootScene.js  завантаження наявних медіа, заглушки
src/scenes/MenuScene.js  меню, керування, гучність
src/scenes/GameScene.js  фізика, бій, HUD, пауза, вихід
src/scenes/RewardScene.js фото, побажання, статистика
src/scenes/EndScene.js   поразка / фінальне привітання
src/lib/                графіка, пошук шляху, медіа, DOM-інтерфейс
```

## GitHub Pages

`vite.config.js` задає `base: '/sanya-exe/'`. Налаштування відповідає [документації Vite для GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages).

1. Створи репозиторій **sanya-exe**, завантаж код у гілку **main**. Після першого `npm install` додай створений `package-lock.json` до репозиторію для фіксації версій залежностей.
2. У репозиторії відкрий **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Push у `main` або ручний запуск **Actions → Deploy sanya.exe to GitHub Pages → Run workflow** запускає тести, збірку й деплой.
4. Гра буде доступна за `https://<username>.github.io/sanya-exe/`.

Для іншої назви репозиторію зміни `base`. Усі URL медіа враховують цей префікс. Не завантажуй `node_modules`; `dist` створює workflow. GitHub Pages публікує всі додані фото та звуки разом із грою.
